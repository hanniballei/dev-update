# 非 npm 开发工具维护

当用户指定非 npm 工具、工具安装来源不明，或要求检查 / 更新全部开发工具时读取本指引。curl / wget 是下载方式，不能据此推断更新机制；以每份实际安装的管理归属选择路径。

## 发现安装

1. 从用户指定目标、当前执行器、现有管理器清单及相关服务入口建立候选集。全量维护还检查已知开发工具入口（例如 Devin、Codex、Pi、uv、rustup）及存在的用户级可执行目录；这是一组发现起点，不是完整支持清单。对 PATH、`~/.local/bin`、`/usr/local/bin` 中可识别的开发工具继续核实来源，只枚举文件，不批量运行陌生程序。项目 `node_modules`、虚拟环境和系统基础包不自动纳入全局维护。
2. Unix 环境可用 `type -a devin` 发现同名入口，再解析链接和包装器。记录稳定入口与解析后的实际路径；更新后链接可能指向新版本，验证时从稳定入口重新解析，不能只运行旧版本目录中的二进制。其他平台使用等效发现方式。
3. 用包管理器的安装记录、官方安装元数据或已核实的官方目录布局确定归属。路径名称、进程名称或命令存在本身不足以证明自管理安装；只读取相关路径与版本字段，不输出认证信息、完整环境或命令历史。服务、容器和宿主捆绑版本核对实际启动来源。
4. 按工具身份、管理器中的包标识、所属用户和实际安装根目录判断是否同一份安装；确认共用同一安装的入口去重，并保留相关服务或进程。仅共用 PATH 目录或 npm prefix 的不同工具不能合并；不同用户、不同安装根目录或不同管理归属分别列项。单工具请求遇到多份安装且无法确定目标时先询问；全量维护逐份列入清单，按现有权限处理。

只使用已安装的管理器，不为发现工具安装新管理器。未安装与无权限查询分别记录；用户仅要求原生工具时，npm 缺失不妨碍独立检查。发现范围之外或来源无法识别的条目列为覆盖缺口，不宣称整台机器所有软件已覆盖。

## 核实能力与选择渠道

每份安装先明确：当前版本、目标版本及发布渠道、只读检查入口、更新入口、安装后验证方式。以对应版本的官方文档、帮助和安装记录交叉核对；帮助和版本探测也应确认不会启动会话或触发自动更新。没有安全探测方式时读取已有元数据并报告未知，不为检查修改配置来关闭自动更新。

| 安装归属 | 处理方式 |
| --- | --- |
| npm | 交给该安装对应的 npm 和 Node 环境，复用 `npm_update.py`；linked / 本地 / Git 来源沿用其跳过规则 |
| Homebrew、pipx、uv tool 或其他包管理器 | 核实该管理器当前版本的检查与定向升级方式，按安装记录中的准确标识处理单个目标；保留 pin、依赖管理关系和渠道 |
| 独立安装且有官方自更新器 | 使用已核实的自更新命令，确认其更新的是目标安装、目标版本或渠道；不假设存在通用 `--check`、`--dry-run` 或 `--version` 参数 |
| 宿主应用、容器或其他管理器捆绑 | 交给对应宿主或部署渠道；宿主更新若超出用户范围或影响其他组件，先确认范围及相关授权。宿主渠道尚未核实时只报告待处理，不覆盖内部二进制 |
| 官方安装器支持原地升级 | 仅在官方确认适用当前平台、架构和原安装位置时采用；先确认目标、下载来源、脚本行为及是否改变配置，按入口审批规则处理影响。不能把首次安装或强制重装当普通升级 |
| 手工二进制、源码、本地修改或来源不明 | 保留现状并报告来源 / 更新方法未核实。核实官方发布与替换流程后才能制定方案，不能猜下载地址、直接覆盖或改装另一渠道 |

管理器若会刷新缓存，区分元数据缓存与安装、配置或运行状态变化；只读检查不应触发后者。某条路径缺少只读查询或无法获得目标版本时，报告“最新版本未确认”；更新任务仍按入口的目标不确定性和审批规则决定是否执行，不把检查失败视为最新。

优先使用官方更新器或所属管理器已有的校验、平台选择和事务机制。确需下载安装器或发布文件时，从已核实的官方地址获取到临时位置，核对官方提供的签名或校验和及升级说明，再按已授权方案执行；校验材料缺失时明确说明，不声称已校验。检查阶段不执行远程安装脚本，更新失败后也不自动用重装兜底。

## Devin

先区分独立 Devin CLI、Homebrew 安装与其他应用捆绑的版本。Devin Desktop、远端服务和 shell 中的 CLI 不能仅凭名称当作同一份安装；CLI 的自更新命令不代表可以升级整个宿主应用。

### 独立 CLI

官方提供以下更新入口；执行前确认命中的稳定入口属于本次目标安装，必要时使用其绝对路径：

```bash
devin update
```

该命令会检查并可能安装更新，只用于已授权的更新阶段。仅检查时，依据当前版本官方能力读取安装版本和发布信息；未确认安全的只读检查方式就报告“最新版本未确认”，不猜测 `devin update --check`。普通更新不追加 `--force`。

macOS / Linux 的自管理安装支持后台自动更新；官方说明通过切换 `current` 链接使下次启动使用新版，当前运行会话不受该切换影响。这不保证所有版本的显式更新命令都具有相同的运行时行为，执行前仍核实当前版本。无需为接入本 skill 修改 `auto_update` 设置。

### Homebrew 与宿主捆绑

官方文档说明，Homebrew 安装应由 Homebrew 更新，示例为：

```bash
brew upgrade devin
```

实际执行使用本机安装记录中的准确 formula / cask 标识与对应参数；不能仅凭示例推断所有版本的包名。只升级选定目标，不运行无目标的整库升级，也不通过 `devin update --force` 绕过管理归属。

其他应用捆绑的 Devin 随宿主更新。定位宿主、其官方更新方式和影响范围后再处理；只有 CLI 更新授权时，不自动扩展成宿主整体升级。

### 验证与自更新

记录更新前后的稳定入口、实际路径和安装版本，再用已确认安全的新进程验证方式核对。当前执行器是该安装时，遵循 [统一执行顺序](../SKILL.md#更新前与执行顺序)，在最后阶段保存日志与剩余动作。磁盘更新成功不能证明旧会话已加载新版；当前会话保持运行，需下一次启动生效的内容单独报告，并沿用 [审批规则](../SKILL.md#审批点必须显式提出)。
